Editorial approach

Updates with context, evidence and controlled status language.

Spacefield news is intended to be factual rather than promotional. Each update should state what changed, what evidence supports the announcement and where readers can find the relevant research, release or company record.

Scientific and software milestones require careful distinction. A completed benchmark is not the same as external validation. A frozen package is not automatically a Production Release. A computational candidate is not an experimentally confirmed result.

Public status language therefore follows the same controlled lifecycle used across the website: Research, Development, Validation, Release Candidate and Production Release.

VerifiedMaterial facts should be supported by a public or internal record.
ScopedAnnouncements should state what the milestone does and does not establish.
PermanentImportant updates should remain accessible rather than disappearing in a social feed.

Communication policy

What readers should expect from Spacefield announcements.

Public updates should be accurate, evidence-linked and explicit about scientific and software maturity.

Where an announcement relates to scientific performance, software availability or candidate molecules, the page should link to the relevant evidence and state the limits of the claim.

01
No unsupported scientific claims

Computational predictions will not be presented as proof of therapeutic efficacy, safety, clinical value or regulatory suitability.

02
No implied public access

Release announcements will state whether software, models, documentation or evaluation resources are public, private or controlled.

03
Controlled status terminology

Updates will use Research, Development, Validation, Release Candidate and Production Release consistently across the website.

04
Visible corrections

Material corrections or superseded statements should remain linked to the original announcement where practical.
