Release philosophy

A release is a defined scientific and engineering state.

Spacefield treats software releases as identifiable research and engineering states rather than as anonymous downloadable files. A release record should state what software and models are included, which interfaces are supported, what evidence has been completed and which limitations remain.

This distinction prevents confusion between exploratory research, active development, controlled validation, near-final release candidates and software that has been formally approved for production use.

Public resources will be activated progressively as documentation, licensing, intellectual-property protection, validation and distribution decisions are completed.

VersionedEvery authorised package carries a defined identity and release state.
TraceableIntegrity hashes, manifests and provenance records connect artefacts to their source.
ScopedAccess rights and scientific claims are stated for each release individually.

Release manifest

What a complete release record should contain.

A release manifest connects the visible version number to the technical and scientific artefacts that define the package.

The exact contents may differ between public, private, evaluation and enterprise distributions, but the governing principle remains the same: users should be able to identify what they received and how it relates to the documented release.

✓
Version identity

Product name, semantic version, release channel and release date.

✓
Software identity

Package hashes, source or build reference, dependencies and supported environment.

✓
Model identity

Model file hashes, endpoint coverage, training reference and predictor parity status.

✓
Scientific scope

Intended use, supported inputs, endpoint definitions and explicit limitations.

✓
Validation record

Benchmark references, authorised metrics, data partitions and evaluation status.

✓
Access and legal record

Licence, confidentiality, redistribution, support and permitted-use conditions.

Integrity and provenance

Verify the artefact before relying on the result.

Integrity records help users confirm that a package or model has not changed since the release manifest was created.

#

Cryptographic hashes

SHA-256 values identify release archives, model artefacts, manifests and other critical files.

≡

Content manifests

File inventories record package members, sizes and integrity information for the distributed build.

↗

Provenance links

Release records connect software, models, benchmark reports, documentation and citation information.

◎

Predictor parity

Where applicable, release testing confirms that packaged predictors reproduce the approved reference outputs.
